# Hermeneia Reader Interface: Translation Layers, Toolbars, and Document Organization

## Origin

This note comes from the Gatsby metaphor essay experiment, especially the third document tab: a Chinese-centered interpretation of *The Great Gatsby* that reframes the argument around reality, relationship, change, time, and continuous adjustment.

The important product insight is that the document is not merely a translation. It is the same interpretive object viewed through a different cultural and philosophical frame.

That makes it a useful prototype for Hermeneia's reader interface.

## Core Insight

Hermeneia should not behave like a normal document viewer.

A normal reader shows text.

Hermeneia should show the movement of understanding:

- what the text says
- what the reader noticed
- what questions emerged
- what interpretations formed
- what evidence supports them
- what changed across translations
- what framework best organizes the whole text

Hermeneia is therefore not just a writing app, note-taking app, translation app, or study tool.

It is an interpretive operating system for texts.

## Reader Interface Model

The reader should present one source as a living interpretive object with switchable layers.

### 1. Original / Source Text

The base document, passage, chapter, scripture, novel excerpt, article, or essay.

### 2. Translation Layer

Multiple forms of translation:

- literal translation
- readable translation
- cultural translation
- academic translation
- theological translation, when appropriate

The key is that translation is not only language conversion. It can reveal how a text changes when interpreted through another conceptual frame.

### 3. Interpretive Layer

This layer answers: What is this text doing?

Possible elements:

- themes
- symbols
- metaphors
- tensions
- claims
- evidence
- unresolved questions
- counterreadings

### 4. Framework Layer

The same text can be viewed through multiple lenses:

- historical reading
- class reading
- metaphor-system reading
- relational/change reading
- Christian moral or theological reading
- philosophical reading
- rhetorical or structural reading

### 5. Reader Notes Layer

Reader-created material:

- questions
- observations
- objections
- insights
- rankings
- tags
- scripture anchors
- unresolved tensions

## Translation Switching

The translation switcher should not work like a basic language selector.

It should show how meaning shifts across versions.

For example, in the Gatsby experiment:

- the English version emphasizes interpretation versus reality
- the Spanish version transfers and reorganizes the structure
- the Chinese version shifts the center of gravity toward reality, relationship, time, change, and continuous adjustment

The underlying claim remains stable, but the philosophical center changes.

### Proposed Feature: What Shifted?

A toolbar action that compares two versions and explains:

- what concepts became more central
- what concepts became less central
- what claims stayed stable
- what terms have no clean equivalent
- what cultural assumptions changed
- what interpretive pressure each language introduced

Example output:

> The English version emphasizes interpretation versus reality. The Chinese version emphasizes adjustment within changing relationships. The core claim remains stable, but the philosophical center moves from epistemology toward relational adaptation.

## Toolbar Groups

Hermeneia's toolbar should operate on meaning, not only formatting.

### Navigation

- document map
- translation switcher
- section jump
- argument outline
- source/reference view

### Interpretation

- identify thesis
- find metaphors
- compare frameworks
- surface unresolved questions
- generate counterreading
- compress argument

### Reader Work

- highlight
- ask question
- add observation
- mark claim
- mark evidence
- rank importance
- add objection
- add theological or philosophical anchor

### Structure

- split into claims
- build outline
- detect redundancy
- show argument flow
- show missing transitions
- show conclusion alignment

### Cross-Language

- literal translation
- cultural translation
- academic translation
- compare translation shifts
- identify terms with no clean equivalent

## Document Organization Model

Hermeneia documents should not be flat files only.

They should be organized as interpretive graphs.

```text
Project
  Work / Source
    Chapter / Section
      Passage
        Notes
        Questions
        Claims
        Metaphors
        Translations
        Counterreadings
        Synthesis
```

The Gatsby essay already points toward this architecture. Its method follows a cycle:

```text
observation -> classification -> question generation -> evidence collection -> hypothesis revision -> verification
```

That cycle can become the core Hermeneia workflow.

## Product Category

Hermeneia is an interpretive operating system for texts.

It helps a reader move through:

```text
text -> observation -> question -> interpretation -> revision -> synthesis
```

This is also the difference between an AI document assistant and a true reader system.

An AI document assistant answers questions about the document.

Hermeneia preserves and structures the reader's path toward understanding.

## Critical Constraint

The interface cannot become only beautiful markdown plus chat.

That would miss the product.

The core value is preserving the movement from raw text to refined interpretation.

The reader must be able to see how meaning changed, why it changed, and what evidence forced the change.

## Scriptural Anchor

Proverbs 18:13 warns against answering before hearing.

Hermeneia should embody that discipline by forcing interpretation to follow observation, evidence, and revision.

Read first. Observe carefully. Ask better questions. Then judge.
